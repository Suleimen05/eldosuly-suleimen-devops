Это шпаргалка для записи с нуля. Читайте фразы из пунктов **«Сказать дословно»**. В пункте **«Показать»** делайте только указанное действие. Команды можно копировать и вставлять: на видео важно показать результат и объяснить его, а не печатать быстро.

**Длительность:** примерно 10–12 минут. Таймкоды — ориентир, а не секундомер: если Docker или Jenkins выполняет команду дольше, дождитесь результата и продолжайте. В задании 10–20 минут указаны как **рекомендация**, поэтому здесь выбран быстрый маршрут около нижней границы. Запись должна быть **одним непрерывным видео с экраном и вашим голосом**.

## Подготовка без записи — 2–3 минуты

1. Запустите Docker Desktop и откройте проект в VS Code.
2. **Закройте вкладку jenkins/.env.** В ней пароль Jenkins; не показывайте файл на записи. До начала видео войдите в Jenkins по адресу http://localhost:8080 под пользователем admin. Пароль возьмите из локального jenkins/.env, но не произносите и не показывайте его.
3. Откройте в браузере вкладки:
   - https://github.com/Suleimen05/eldosuly-suleimen-devops
   - http://localhost:8080/job/Eldosuly_Suleimen_DevOps/
   - http://localhost:8000
4. Откройте терминал **PowerShell** в VS Code. Один раз до записи выполните:

~~~powershell
Set-Location 'C:\Users\PC\Desktop\девопстаск6\eldosuly_suleimen'
docker ps --filter name=eldosuly-suleimen
~~~

Если в списке нет Linux-контейнера, выполните docker start eldosuly-suleimen-linux. Если нет Jenkins, выполните docker start eldosuly-suleimen-jenkins и дождитесь открытия страницы 8080. Проверьте микрофон и увеличьте шрифт терминала до читаемого размера.

**Важная подсказка:** после команды docker exec -it eldosuly-suleimen-linux bash вы будете внутри Linux. После команды exit снова вернётесь в PowerShell. Команды для Linux и PowerShell ниже разделены специально.

## 1:05–1:35 — создать, скопировать, переименовать, удалить

**Показать в Linux:**

~~~bash
mkdir -p backup/demo
touch backup/demo/first.txt
cp backup/demo/first.txt backup/demo/copy.txt
mv backup/demo/copy.txt backup/demo/renamed.txt
ls backup/demo
rm backup/demo/renamed.txt
head -n 3 Eldosuly_Suleimen_info.txt
tail -n 2 Eldosuly_Suleimen_info.txt
~~~

**Увидеть:** после ls видны first.txt и renamed.txt; head показывает начало файла, tail — конец.

**Сказать дословно:**

> mkdir создал папку, touch — пустой файл, cp сделал копию, mv переименовал её, а rm удалил. head показывает первые строки файла, tail — последние. Это основные операции с файлами в Linux.

## 1:35–2:00 — поиск в логах

**Показать в Linux:**

~~~bash
find . -name application.log
grep ERROR logs/application.log
grep WARNING logs/application.log
grep -c ERROR logs/application.log
tail -n 5 logs/application.log
~~~

**Увидеть:** grep -c ERROR выводит число 2.

**Сказать дословно:**

> find нашёл файл журнала. grep отбирает строки с ошибками и предупреждениями. В учебном журнале две строки ERROR, это подтверждает число два. tail показывает последние записи, что удобно при проверке работы приложения.

## 2:00–2:25 — права доступа

**Показать в Linux:**

~~~bash
chmod 600 private.txt
chmod 644 public.txt
ls -l private.txt public.txt
~~~

**Увидеть:** у private.txt права -rw-------, у public.txt — -rw-r--r--.

**Сказать дословно:**

> chmod меняет права доступа. Число 600 означает, что закрытый файл может читать и менять только владелец. Число 644 даёт владельцу чтение и запись, а группе и остальным — только чтение. Буквы r, w и x означают читать, записывать и выполнять. Так закрытый файл защищён от других пользователей.

**Сказать дословно:**

Процесс — работающая программа; PID — её номер. ps показывает список и владельца процесса, top — его нагрузку на процессор и память. Теперь я вышел из Linux обратно в PowerShell.

## 4:05–4:35 — Dockerfile

**Показать:** в VS Code откройте Dockerfile. Проведите курсором по строкам сверху вниз.

**Сказать дословно:**

> Dockerfile — инструкция для создания образа приложения. FROM берёт Python как основу. WORKDIR задаёт рабочую папку, COPY добавляет файлы, RUN проверяет Python-код и права скрипта. EXPOSE указывает порт 8000, CMD запускает приложение. Образ — готовый пакет, а контейнер — запущенный экземпляр этого пакета.

**Сказать дословно:**

## 6:05–6:45 — Docker Compose

**Показать:** на несколько секунд откройте docker-compose.yml, затем вернитесь в PowerShell и выполните:

~~~powershell
docker rm -f eldosuly-suleimen-container
docker compose up -d --build
docker compose ps
(Invoke-WebRequest 'http://localhost:8000/health' -UseBasicParsing).StatusCode
(Invoke-WebRequest 'http://localhost:8000/health' -UseBasicParsing).Content
docker compose down
~~~

**Увидеть:** у проверки /health код 200 и текст OK. После down приложение временно остановлено: Jenkins запустит его заново в следующем разделе.

**Сказать дословно:**

> Compose хранит настройки сборки, порта и переменных в одном YAML-файле. Команда up подняла сервис, ps показала его состояние. Проверка health вернула 200 и OK, значит приложение отвечает. Команда down остановила этот экземпляр; дальше Jenkins сам соберёт и запустит приложение.

## Если что-то пошло не по плану во время записи

- **Команда заняла дольше таймкода:** молча дождитесь результата и переходите к следующему блоку. Таймкод не надо произносить.
- **Jenkins ещё работает:** скажите: «Сборка пока выполняется; я жду итоговый статус», затем дождитесь SUCCESS.
- **Появилась ошибка:** покажите её и исправьте. Если исправление заняло много времени, начните новую цельную запись; не склеивайте фрагменты.
- **Случайно открыли jenkins/.env:** закройте вкладку и начните запись заново, чтобы пароль не попал в сдаваемый файл.
