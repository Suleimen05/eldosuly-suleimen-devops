# Простая видеозащита DevOps за 8–9 минут

Этот сценарий сделан для записи **одним дублем**. Читайте текст после слов **«Говорю»** почти дословно. Команды копируйте блоками. Всего один заход в Linux через терминал, один выход обратно в PowerShell; после терминала переходите к файлам и браузеру.

В задании видео обязательно, а **10–20 минут — рекомендованная длительность**. Этот маршрут короче: примерно 8–9 минут, если всё запускается без задержек. Преподаватель может оценивать полноту демонстрации, поэтому не пропускайте блоки. Если сборка займёт дольше, спокойно дождитесь результата.

## Подготовить до начала записи

1. Запустите Docker Desktop. Откройте папку проекта в VS Code и один встроенный терминал **PowerShell**.
2. **Закройте вкладку jenkins/.env**: там пароль. Войдите в Jenkins заранее: http://localhost:8080 , логин admin, пароль смотрите в локальном jenkins/.env без записи экрана.
3. Откройте в браузере три вкладки: [GitHub](https://github.com/Suleimen05/eldosuly-suleimen-devops), [Jenkins Job](http://localhost:8080/job/Eldosuly_Suleimen_DevOps/) и http://localhost:8000 . Последнюю вкладку пока не обновляйте.
4. В терминале заранее выполните:

~~~powershell
Set-Location 'C:\Users\PC\Desktop\девопстаск6\eldosuly_suleimen'
docker ps --filter name=eldosuly-suleimen
~~~

Если нет Linux-контейнера, выполните docker start eldosuly-suleimen-linux. Если нет Jenkins, выполните docker start eldosuly-suleimen-jenkins и дождитесь загрузки страницы 8080. Увеличьте шрифт терминала и проверьте микрофон. **Запись включайте только после этой подготовки.**

## 1:00–1:25 — работа с файлами

**В Linux вставляю:**

~~~bash
mkdir -p backup/demo
touch backup/demo/a.txt
cp backup/demo/a.txt backup/demo/b.txt
mv backup/demo/b.txt backup/demo/c.txt
ls backup/demo
rm backup/demo/c.txt
head -n 2 Eldosuly_Suleimen_info.txt
tail -n 2 Eldosuly_Suleimen_info.txt
~~~

**Говорю:**

> mkdir создаёт папку, touch — файл, cp копирует, mv переименовывает, rm удаляет. head показывает начало файла, tail — конец. Пробные файлы находятся в backup, которую Git игнорирует.

## 1:25–1:50 — поиск ошибок

**В Linux вставляю:**

~~~bash
find . -name application.log
grep ERROR logs/application.log
grep WARNING logs/application.log
grep -c ERROR logs/application.log
tail -n 5 logs/application.log
~~~

**На экране:** число ошибок — 2.

**Говорю:**

> find находит журнал, grep выводит ошибки и предупреждения. Здесь две строки ERROR. tail показывает последние пять записей журнала.

## 1:50–2:20 — права, скрипт и процессы

**В Linux вставляю:**

~~~bash
chmod 600 private.txt
chmod 644 public.txt
ls -l private.txt public.txt
./scripts/Eldosuly_Suleimen_system.sh
ps aux | head -n 5
top -b -n 1 | head -n 8
exit
~~~

**Говорю:**

> chmod 600 разрешает читать и менять закрытый файл только владельцу. При 644 группа и остальные могут читать открытый файл. Буквы r, w, x означают чтение, запись и запуск. Bash-скрипт выводит мои данные и сведения о системе. Процесс — работающая программа, PID — её номер; ps показывает список процессов, top — нагрузку на процессор и память. Командой exit я один раз вышел обратно в PowerShell.

## 3:25–4:05 — Docker Compose

**Всё ещё в том же PowerShell, вставляю по одной строке:**

~~~powershell
docker rm -f eldosuly-suleimen-container
docker compose up -d --build
docker compose ps
(Invoke-WebRequest 'http://localhost:8000/health' -UseBasicParsing).StatusCode
docker compose down
~~~

**На экране:** Compose запускает контейнер; проверка возвращает 200. После down приложение временно выключено. **Следующий запуск Jenkins снова его поднимет.**

**Говорю:**

> Compose собирает и запускает приложение по настройкам из одного файла. Сейчас контейнер запущен, а проверка health вернула код 200 — значит, приложение отвечает. Я остановил Compose; дальше Jenkins автоматически создаст и запустит контейнер снова.

**После этого терминал больше не нужен.** Оставьте его открытым, чтобы не тратить время на закрытие и повторное открытие.

## Если возникла пауза

- Если Docker или Jenkins работает дольше, просто дождитесь окончания. Таймкоды вслух не произносите.
- Если Jenkins ещё собирает, скажите: «Сборка ещё идёт, я жду итоговый статус».
- Если команда показала ошибку, разберитесь и начните новую цельную запись, когда всё работает.
- Пароль из jenkins/.env не показывайте. Открытую вкладку .env закройте **до записи**.
